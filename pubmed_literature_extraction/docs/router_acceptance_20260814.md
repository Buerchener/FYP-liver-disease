# 多维复杂度与两阶段路由验收报告（2026-08-14）

## 结论

本轮实现保留为**影子路由**，未获得生产执行权。生产默认仍为 `router_execution_mode=legacy`；`active_shadow` 仅允许 `skip_neo4j_write=true`，若尝试写库会直接拒绝启动。

画像与路由分类门槛已经通过，但端到端质量与性能门槛未全部通过。因此不能仅凭调用量下降就上线。

- 工具边际收益、延迟、token、缓存命中与路由审计报告。

## 安全判断

- Neo4j全程只读，实际写入为0。
- 新路由没有生产权限；危险错误写入为0。
- `Safe Write Precision`代理指标下降，故按门槛阻止晋升。
- 50篇中第二LLM调用1次，产生1次编辑和1次拒绝；远程工具节省显著，但不足以抵消主抽取长尾与抽取随机性。

## 下一轮建议

1. 固定主抽取候选做配对重放，先只激活验证后的工具门控，避免把主模型随机性误算为路由收益。
2. 将抽取前路由（Golden-shot、chunk、提示策略）拆成独立消融实验，每次只改变一个因素。
3. 运行至少3次50篇重复实验，报告中位数与P95；单次wall-clock不适合作为晋升依据。
4. 在保持候选完全相同的条件下验证 Strict import-ready precision 与关系F1；只有都过线才考虑扩大只读激活范围。
